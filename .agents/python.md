# Python

## Lab 2 — pure Python, no Scade involvement

- `src/lab2/starter/lab2_cruise_control_starter.py` — student entry point.
  Constants `OFF`/`ACTIVE`/`SUSPENDED` (do not change). Stub function
  `update_cruise_control(current_state, speed, brake_pressed,
  driver_activates, driver_reactivates)` — body is 4 commented steps, no
  logic, falls through to `return current_state`. `run_tests()` runs 7
  hardcoded cases (TC-01…TC-07, tagged with REQ IDs) and prints a
  PASS/FAIL table + `"VALIDATION: ALL REQUIREMENTS MET."` /
  `"VALIDATION: ISSUES FOUND"` banner.
- `src/lab2/solution/lab2_cruise_control_solution.py` — instructor-only
  reference implementation of the same function (brake/overspeed →
  SUSPENDED; SUSPENDED requires explicit `driver_reactivates`, not just
  `driver_activates` — the "key trap" REQ-04 case; OFF→ACTIVE requires
  speed ≥ 30). Same test table/output format as the starter.
- `docs/lab2/index.html` embeds the identical starter file as a JS
  `STARTER_CODE` template literal, executed in-browser via **Skulpt**
  (loaded from `https://skulpt.org/js/skulpt.min.js` +
  `skulpt-stdlib.js`, remote/CDN — no local vendoring). `runCode()` calls
  `Sk.configure(...)` then
  `Sk.misceval.asyncToPromise(() => Sk.importMainWithBody('<stdin>', false,
  editor.getValue(), true))` and colorizes PASS/FAIL lines in the output pane.
  No third-party packages are imported anywhere in Lab 2 (stdlib only), which
  is why it runs unmodified under Skulpt.
- **Local run:** `python lab2_cruise_control_starter.py` — expect 7 PASS
  lines + the "ALL REQUIREMENTS MET" banner once implemented correctly.

## Lab 3.1 — Scade One Python wrapper testing

- `src/lab3_1/solution/requirements.txt`: `ansys-scadeone-core==0.8.2`
  (pinned).
- `src/lab3_1/solution/setup_wrapper.py` — hand-authored. Imports
  `ansys.scadeone.core.ScadeOne` and
  `ansys.scadeone.core.svc.pywrapper.python_wrapper.PythonWrapper`. Points at
  a local Scade One install (`SCADE_INSTALL = r"C:\Program Files\Ansys
  Inc\v261\Scade One Student\Scade One"`) and a project path, then calls
  `PythonWrapper(prj, "CodeGenerationJob_limiter",
  output="limiter_wrapper").generate()` (and the counter equivalent) — this
  script *produces* the generated wrapper folders below. **Requires a local
  Scade One installation; cannot be run without it.**
- `src/lab3_1/solution/counter_wrapper/counter_wrapper.py`,
  `limiter_wrapper/limiter_wrapper.py` — **generated** (`# generated by
  PyScadeOne Wrapper 1.0`, line 1 of each). `ctypes`-based DLL loaders
  exposing `Inputs`/`Outputs` and `reset()`/`cycle()`.
- `src/lab3_1/solution/test_counter.py` — "Mirrors the multi-cycle simulation
  from Activity 4D." Drives `counter_wrapper` through `expected_sequence =
  [0,1,2,3,4,5]`, one `reset()` + 6 `.cycle()` calls, manual PASS/FAIL print.
- `src/lab3_1/solution/test_limiter.py` — "Mirrors the 3 manual simulation
  steps from Activity 2D." 3 cases (pass-through, clamp-max, clamp-min),
  tolerance `1e-9`, manual PASS/FAIL print.
- **Local run:** requires Scade One installed + wrappers generated via
  `setup_wrapper.py` first; then `python test_counter.py` /
  `python test_limiter.py`.

## Lab 3.2 — Scade One Python wrapper, cruise-control system

- `src/lab3_2/solution/CruiseControl/requirements.txt`: `ansys-scadeone-core`
  (**unpinned** — inconsistent with Lab 3.1's pinned version; document, don't
  silently "fix" by inventing a pin) plus `matplotlib` (added this session
  for the Part 6 evaluation-script rewrite, see below).
- `src/lab3_2/solution/CruiseControl/generate_python_wrapper.bat` — hand
  script invoking `py -3 -m ansys.scadeone.core.cli pycodewrap --install-dir
  "...v261..." --job "CodeGenerationJob0" --out "cc_wrapper" "...CruiseControl.sproj"`.
- `cc_wrapper/cc_wrapper.py`, `cc_wrapper.c`, `cc_wrapper.def` — **generated**
  (banner on line 1 of each). `cc_wrapper.py` defines `main_CC_design_Inputs`
  (`brake`,`accel`,`on`,`res`,`set_point`), `main_CC_design_Outputs`
  (`speed_out`,`gear_out`,`rpm_out`), state enums `SSM_ST_SSM1`/`SSM_ST_SSM2`,
  and a `main_CC_design` ctypes wrapper class with `reset()`/`cycle()`.
- `src/lab3_2/solution/CruiseControl/tester.py` — a **live console demo, not
  an automated test**: 1000-cycle loop toggling `accel`/`on`/`res`/`set_point`
  with `time.sleep(0.05)` between prints; no assertions, no PASS/FAIL output.
  Kept as-is; no longer part of the lab.md lesson flow.
- `docs/lab3_2/lab.md` Part 6 (rewritten this session) teaches
  `evaluate_cc.py` — **and this one does exist in the repo**, at
  `src/lab3_2/solution/CruiseControl/evaluate_cc.py`, alongside six example
  scenario files under `src/lab3_2/solution/CruiseControl/scenarios/`
  (`tc01`…`tc06`, one CSV per test case, one row per simulation cycle, an
  optional `expected_throttle`/`req`/`note` checkpoint). It illustrates the
  same hypothetical wrapper API as the snippet it replaces (`cc.on`,
  `cc.brake`, `cc.cycle()`, `cc.throttle`), which still differs from the real
  generated `cc_wrapper.py`'s `.inputs.<name>`/`.outputs.<name>` pattern —
  both lab.md and `evaluate_cc.py` carry the same "check the generated
  wrapper file" caveat as before; this session did not resolve that gap, only
  replaced the un-backed instructional snippet with a real, committed script.
- **Local run:** requires Scade One installed + `cc_wrapper` generated first,
  plus `matplotlib`; then `python evaluate_cc.py` (writes `results/*.csv` +
  `results/plots/*.png`, prints a PASS/FAIL banner) or `python tester.py`
  (prints a live trace, does not assert correctness).

## Correspondence between the Python reference and the Scade models

Explicitly stated by the repo itself, not inferred:
- `test_limiter.py`/`test_counter.py` docstrings say they "mirror" specific
  Lab 3.1 simulation activities.
- `docs/lab3_2/lab.md` states the wrapper test "mirrors the test cases from
  Lab 2" and tells students to "compare the output to Lab 2's verification
  report."
- There is **no automated cross-check** between Lab 2's Python state machine
  and Lab 3.2's Swan `cruise_control` node — the correspondence is manual
  (a human runs both and compares printed output).
