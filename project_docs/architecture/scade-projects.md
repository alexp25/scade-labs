# Scade One projects — architecture

Two independent Scade One projects exist, both under `src/`, both reference
solutions (no student-editable starter — these labs are GUI-modeling
exercises, not code-stub exercises).

## Lab 3.1 — `src/lab3_1/solution/` (`demo.sproj`)

**Project manifest** `demo.sproj` — plain JSON:
```json
{ "Version": "1.0", "Name": "demo", "Dependencies": [], "Resources": [] }
```

**Model source** `assets/blocks.swan` (Swan `2025.2`/graph `2.1`), hand-authored:
- `function limiter(value_in, min, max: float64) returns (value_out: float64)`
  — diagram-form double clamp (`if value_in > max then max else value_in`,
  then clamped again against `min`).
- `node counter(init_value, step: int32) returns (count: int32)` — a `pre`
  block feeds back `count`, summed with `step` each cycle; `init_value` seeds
  the first cycle.
- `const init: float64 = 0;`

**Test harness** `assets/test.swant` — hand-authored, **populated**:
- `_harness harness_counter` — instantiates `blocks::counter` as
  `$my_counter` (`#pragma swt under_test`), wires `1_i32`→`step`,
  `0_i32`→`init_value`, `_stop_condition` wired to `false` (a Scade One
  harness default — no need to wire this explicitly; see
  `project_docs/verification/testing-and-simulation.md`).
- `_harness harness_limiter` — instantiates `blocks::limiter` as
  `$my_limiter`, wires `120.0_f64`→`value_in`, `0.0`→`min`, `100.0`→`max`.

**Generated Python wrapper** `counter_wrapper/`, `limiter_wrapper/` — each
`.py` begins `# generated by PyScadeOne Wrapper 1.0` and loads a sibling
`.dll` via `ctypes`. Regenerated by `setup_wrapper.py` (hand-authored driver,
imports `ansys.scadeone.core.ScadeOne` and
`ansys.scadeone.core.svc.pywrapper.python_wrapper.PythonWrapper`), which
requires a local Scade One install at
`C:\Program Files\Ansys Inc\v261\Scade One Student\Scade One`.

## Lab 3.2 — `src/lab3_2/solution/CruiseControl/` (`CruiseControl.sproj`)

**Project manifest** — plain JSON, declares one `SimulationData` resource
(`resources/main_inputs.sd`).

**Model sources**, all hand-authored Swan `2025.2`/graph `2.1`:
- `assets/CC_design.swan`:
  - `node cruise_control(v_speed, brake, accel, on, res, set_point: ...)
    returns (throttle: float32)` — annotated `#pragma requirement reQ2`
    (the only requirement-traceability tag present in the model — see
    `project_docs/verification/requirements-and-traceability.md`). Body is a
    **nested automaton**: outer states `cc_disabled` (initial) /
    `cc_enabled`; `cc_enabled` contains an inner automaton `cc_active`
    (initial) / `cc_standby`. Transitions: `on` (disabled→enabled);
    `brake>10.0 or accel>10.0` (active→standby); `res and brake<10.0`
    (standby→active).
  - `node regulator(set_point, speed: float32) returns (throttle: float32)`
    — proportional term (`0.5 * error`) + integral accumulator (`pre` with
    gain `0.2`), summed then clamped by two `limiter` instance blocks
    (`[-100,100]` then `[0,100]`).
  - `node limiter(input, upper_limit, lower_limit: float32) returns (output:
    float32)` — same clamp pattern as Lab 3.1's `limiter`, `node`/float32 form.
- `assets/Car_design.swan` — vehicle plant model: `node car(throttle_percent,
  brake: float32) returns (speed, rpm: float32; gear: int32)`. Gear selection
  via a `case` construct over speed thresholds (20/40/70/100/130 km/h),
  rolling/drag/brake force constants, `pre`-based speed integration.
- `assets/Simulation.swan` — wires the above together:
  `node main(...)` (closed loop, car speed feeds cruise control, cruise
  control throttle feeds car) and `node main_manual(...)` (open loop,
  `throttle_percent = accel*100.0`, no cruise control — plant-only
  exploration).

**Test harness** `assets/Main_test.swant` — **present but empty**: only the
version header, no `_harness` body. Lab.md describes test-harness activities
for this lab, but no test vectors are actually committed here — building
this out is left to the student/instructor, not shipped as a reference.

**Generated artifacts**, `cc_wrapper/`:
- `cc_wrapper.py`, `cc_wrapper.c`, `cc_wrapper.def` — generated
  (`generated by PyScadeOne Wrapper 1.0` banner). `cc_wrapper.py` defines
  `main_CC_design_Inputs` (`brake`,`accel`,`on`,`res`,`set_point`),
  `main_CC_design_Outputs` (`speed_out`,`gear_out`,`rpm_out`), enums
  `SSM_ST_SSM1`/`SSM_ST_SSM2` for the two automaton nesting levels, and a
  ctypes-backed `main_CC_design` class (`reset()`/`cycle()`).
- `cc_wrapper.dll` — **compiled binary, not inspectable**: 94,820 bytes,
  PE32+ DLL (x86-64, Windows), verified by file signature only.
- `swan_config.h` — Ansys-copyrighted vendor runtime header, not
  student/instructor source.
- `py_wrapper_files.txt`, `swan_cg_files.txt` — generator-produced manifests
  of the wrapper's and codegen job's own output filenames (the `.c`/`.h`
  files they list, e.g. `main_CC_design.c`, are **not checked into this
  directory** — only the manifest is).
- `resources/main_inputs.sd` — **binary/opaque**, 465 bytes, magic `S1SDJ` +
  compressed data; embedded strings (`brake`,`accel`,`on`,`res`,`set_point`)
  match the model's input names, consistent with a saved simulator
  "SimulationData" resource.

## Verified tooling/version facts (quoted, not inferred)

- Swan/graph format header identical in every `.swan`/`.swant` file:
  `-- version swan: 2025.2 graph: 2.1` (`.swant` adds `swant: 1.1`).
- Scade One install path (both labs' scripts):
  `C:\Program Files\Ansys Inc\v261\Scade One Student\Scade One` — implies
  Scade One **v261**; no separate semantic product version string was found
  anywhere in the repo.
- Python `3.12` required for wrapper generation/testing (`py -3.12 ...`, used
  consistently across both labs' scripts and `lab.md` files).
- `ansys-scadeone-core==0.8.2` pinned for Lab 3.1;
  **unpinned `ansys-scadeone-core`** for Lab 3.2 — a real inconsistency
  between the two labs' stated dependencies, documented but not silently
  "fixed" here (pinning it would require a maintainer decision about which
  version was actually used to generate the shipped `cc_wrapper.*` files).
- The repo's own `docs/lab3_1/lab.md` warns: "The exact class name and
  instantiation method depend on your Scade One version and project name —
  check the generated wrapper file" — an acknowledged version-drift risk in
  the generated wrappers, not something this documentation pass can resolve
  without a Scade One install.

## Do not hand-edit

Anything with a `generated by PyScadeOne Wrapper 1.0` banner, any `.dll`,
`swan_config.h`, the two generator manifest `.txt` files, or
`resources/main_inputs.sd`. Regenerate via `setup_wrapper.py` /
`generate_python_wrapper.bat` — both require a local Scade One installation,
unavailable in the environment used for this documentation pass (see
`project_docs/verification/testing-and-simulation.md`).
